# Cabal test extensions

Run `forge build` and `forge test`. No additional dependencies, RPC, environment variables, FFI, or configuration changes are required. The original contributor tests remain unchanged.

- `AdversarialOracle.t.sol`: post-signature mutation of every one of the fifteen attestation fields plus the answer encoding; domain name/version/chain/verifier binding; high-s, invalid-v and malformed-length signatures; callbacks with unavailable external dependencies; zero-price and zero-ID handling; failed payment retry; terminal-request replay; attestations issued before submission; identical questions from different users or after a rejection; the zero and explicit `oracleVerifier` settings; timeout boundaries; every invalid owner configuration boundary and the largest accepted values.
- `QuestionProperties.t.sol`: independent JSON-parser round trips over untrusted printable ASCII, quotes, backslashes, DEL, injection-shaped text, empty reasons, all UTF-8 widths at 280/281 characters, and malformed UTF-8; every control character and the guillemet delimiters refused in any position while other characters sharing their lead byte pass. Checks that the stored escaped question is what a parser reads back, that the callback's `questionHash` is the canonical sorted-key keccak of the parsed body with the attested window, the immutable JSON policy fields, the per-definition limit, and the 2000-character bound at the widest values the gate can print.
- `EconomicProperties.t.sol`: fee and price arithmetic boundaries, real swaps across the 400-unit fee threshold, repeated buy/sell cycles without profit, allowance failure/retry, and sell-slippage rollback including cost basis and pool price. Each fuzz property runs 1,000 cases.
- `invariant/CabalInvariant.t.sol`: two campaigns, one for each IMD/CABAL ordering, each with 256 random sequences of 64 actions. Three users submit, approve/reject, execute, clear, transfer, donate, compound, and encounter configuration changes and time advances. Handler reverts fail the campaign; expected failures are asserted explicitly. A deterministic handler test verifies that buys, sells, callbacks, failures, clears, and compounding are reachable.

The invariants require fixed supply and conservation across every participating account; exact oracle charges; gate balances equal to unsolicited donations; equal burn/POL fees derived from the real PoolManager's swap deltas; zero residual settlement deltas and temporary approvals; request states matching the independent action history; and actual hook-owned position liquidity matching cumulative liquidity-addition events. Failed executions must preserve balances, pool price, fee accounting, request state, and holding records. The handler does not infer the expected fee from the hook's own fee counters.

Ordinary bounded trades use 400 minor units through 1,000 tokens, within the seeded pool's depth. Dedicated unit/fuzz tests cover smaller fee boundaries and full integer arithmetic. Random transfers can leave cost-basis records stale until the next gate interaction; the suite does not assert continuous ownership or known basis for transferred-in tokens.

These are offline integration tests using production CABAL, Gate, Hook and Uniswap PoolManager code. IMD and Intake are local mocks. They do not verify deployed mainnet contracts or resolve the truncated oracle wire schema in the assignment. A live factory/oracle rehearsal remains outside this offline suite; the implementation's reconstructed schema and verifier address still need confirmation against the actual oracle.
